# Тест-план тестирования приложения SignalGenerationProgram

## 1. Объект и цели тестирования
* **Объект тестирования:** Десктопное приложение `SignalGenerationProgram` (WPF, .NET Framework 4.8), предназначенное для генерации математических сигналов (Синусоида, Меандр, Треугольный, Пилообразный), расчета их характеристик и экспорта данных.

* **Цели тестирования:**

  * Проверить соответствие реализованной бизнес-логики требованиям технического задания.

  * Убедиться в корректности математических расчетов (Max, Min, Avg) и стабильности отрисовки графиков.

  * Проверить надежность защитных механизмов интерфейса (валидация ввода) при некорректных действиях пользователя.

  * Убедиться в корректности интеграционного взаимодействия с файловой системой (выгрузка CSV) и локальной СУБД SQLite.

## 2. Виды тестирования
* **Функциональное тестирование:** Построчная сверка работы генераторов всех типов сигналов, заполнения интерфейсной таблицы `points_data_grid` и проверки сброса состояния через кнопку очистки формы «⎚».

* **Негативное тестирование:** Проверка устойчивости интерфейса к вводу буквенных символов, пустых значений, отрицательных параметров, а также чисел, выходящих за рамки допустимых ТЗ лимитов выборки (менее 100 или более 10 000 точек).

* **Исследовательское тестирование:** Проведение свободных тестовых сессий без жестких сценариев для поиска скрытых аномалий, архитектурных уязвимостей кодовой базы и багов MVVM/инкапсуляции.

* **Автоматизированное UI-тестирование:** Проектирование Data-Driven сценариев на фреймворке NUnit 4 с использованием движка автоматизации `FlaUI (UIA3)` для быстрой регрессионной проверки интерфейса.

* **Интеграционное тестирование:** Независимая проверка структуры сгенерированных CSV-файлов в папке `SaveData` и прямое программное чтение записей из базы данных `signals.db` через клиент `Microsoft.Data.Sqlite`.

* **Тестирование производительности:** Проверка стабильности работы графического конвейера LiveCharts при отрисовке граничных массивов данных (от 5 000 до 10 000 точек).

## 3. Тестовое окружение
* **Аппаратное обеспечение:** ПК / Ноутбук архитектуры x64.

* **Операционная система:** Windows 10 / Windows 11.

* **Среда разработки и тест-раннер:** Microsoft Visual Studio 2026.

* **Целевая платформа тестов:** .NET 10.0-windows.

* **Вспомогательное ПО:** DB Browser for SQLite, Microsoft Excel.

## 4. Критерии начала и окончания тестирования
* **Критерии начала тестирования:**

  * Предоставлена стабильная скомпилированная сборка приложения `SignalGenerationProgram.exe`.

  * Развернута базовая папка проекта, структура каталогов решения позволяет считывать относительные пути.

  * Подготовлено тестовое окружение и установлены необходимые NuGet-пакеты автоматизации.

* **Критерии окончания тестирования:**

  * Выполнены все спроектированные ручные тест-кейсы и зафиксированы их статусы.

  * Успешно выполнены все разработанные параметризованные автотесты.

  * Все обнаруженные дефекты (12 критических, мажорных и минорных багов) подробно описаны в баг-репорте.

  * Оформлены все требуемые QA-артефакты.

## 5. Риски и способы их снижения
* **Риск 1: Зависание и блокировка автотестов из-за модальных окон.**

  * *Описание:* Появление системных `MessageBox.Show()`, вызванных негативными тестами, блокирует поток автоматизации.

  * *Снижение:* Реализован обходной путь перехвата окон верхнего уровня по уникальным дескрипторам `NativeWindowHandle` средствами FlaUI, позволяющий проверять факт ошибки без замерзания тестов.

* **Риск 2: Нестабильность тестов из-за загрязнения базы данных SQLite.**
  * *Описание:* Повторный запуск тестов копит мусорные строки в таблицах, что искажает результаты расчетов.

  * *Снижение:* В блоке инициализации `[SetUp]` прописана принудительная очистка и пересоздание файла базы данных перед каждым отдельным тестом.

* **Риск 3: Скрытый краш UI-потока при больших нагрузках.**
  * *Описание:* Отсутствие асинхронности в приложении валит автотесты COM-ошибками (`COMException 0x80040201`) на 5000+ точках.

  * *Снижение:* Позитивные автотесты ограничены стабильным диапазоном (до 1000 точек), а критическое зависание на больших массивах вынесено в изолированный тест производительности, фиксирующий баг через свойство `_application.HasExited`.
